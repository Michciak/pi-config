# Pi Remote cockpit

The reference distribution is pinned to pi-web-ui 0.97.0 (npm tarball SHA1 722e211703e65787dc0b279e7e7aa8d96ec394a6). Copyright (c) 2026 xing-shuyin; MIT license in pi-web-ui-LICENSE.txt. PWA PNG icons, four CSS-variable-only themes and the full server SDK are adapted from that distribution. The host runs inside the existing Control Service; Pi remains the only persistent agent runtime. Pi Remote pins Pi 1.0.3 in its independent release; it does not change the separately installed global CLI.

The extension bridge reads canonical goal-state and todo tool-result entries from the current Pi branch. It listens to pi-dynamic-workflows:lifecycle and reads the extension's small run heads for phase, agents and usage. It never saves workflow child transcripts. Generic widgets and statuses are durable SQLite snapshots; questions and approvals retain their existing exactly-once contract.

Following the user's explicit full-SDK decision, the pinned PluginManager covers client mount/send/onData/renderers/UI actions, server activate/cleanup, messages, settings/storage/encrypted secrets, commands, agent tools and guards, events, filesystem access/grants/watchers, outbound network grants, HTTP routes and HTTP/WebSocket loopback proxies, persistent schedules, background tasks, project/SCM APIs, conversation reads/prompts/steer/abort/chat and isolated LLM completion. Selected-conversation snapshots use the existing Pi RPC session. Isolated completion has no tools/extensions, is bounded to four concurrent calls and aborts/disposes on timeout or shutdown. Plugin prompt file-reference attachments are rejected explicitly rather than silently discarded, matching the upstream text-only conversation-writer adapter. No DSH service, Electron shell, second production server or automatic catalog installs are included.

Installation is local, requires explicit manifest permissions, reviews a content digest and keeps previous versions plus storage/secrets/schedules on upgrade. Empty permissions are fail-closed (unlike upstream's legacy compatibility fallback). DOM client bundles require explicit consent. Server plugins remain trusted code, not sandboxed code; browser-side JavaScript is also trusted and CSP is not a DOM sandbox. Revoking an already running client bundle should be followed by refreshing the page. Path grants are persistent and revocable; network grants may be session-only or remembered. New tools and commands become available on reopening a Pi session.

Local APIs guard terminal, direct bash, workspace writes/uploads, Git mutation, plugins, providers and extension updates with LOCAL_ADMIN_REQUIRED. Remote file/Git reads are limited to registered workspace roots. Credential files are refused. Text writes require an ETag, keep file modes and use an atomic replacement; uploads refuse to overwrite an existing file.

Build: npm run build:release. The release contains independent compiled code, web assets and dependencies. Install: scripts/install-web-control.py; restart: scripts/restart-web-control.py. The installer backs up SQLite with SQLite's online backup, global settings, extensions, installed npm extensions and LaunchAgent, and atomically updates runtime/current. Old releases are retained. Never overwrite the active web dist.

Validation: npm run typecheck; npm test; npm run test:e2e; node scripts/smoke-pi-runtime.mjs; node scripts/smoke-startup.mjs; node scripts/smoke-release.mjs; node scripts/smoke-pwa.mjs; python3 tests/restart-web-control.test.py. Native PTY and browser tests require local OS process permissions. SDK LLM tests use a local simulated provider, never paid requests. PWA regression checks a production release offline, all split JS assets, API cache exclusion and an explicit waiting-worker update banner.
